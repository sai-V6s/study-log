●Railsにおける多言語化  

【i18n】  
ソフトウエアを様々な言語や地域設定に対応できるように設計することを意味する用語。  

【YAMLファイル】  
YAMLとはデータを表現するフォーマットのことで、  
YAMLのフォーマットで作成されたファイルがYAMLファイル。  
このフォーマットではデータが階層構造で記述されており、またキーと値のペアで情報が整理されている。  
Railsでは、config配下にモデルとビュー用にそれぞれ多言語化のymlファイルを用意するのが一般的  

【gem'rails-i18n'】  
Railsで作成されたアプリを多言語化させるためのライブラリ。  
config/application.rb に設定を記述することでデフォルトの言語を設定できる。  
gemfaileに同様にi18nの導入を記述する。  
その後dokckerでinstallを行う。  

erb側の記述方法  
例)
```
<li class="nav-item">
    <%= link_to t('header.login'), login_path, class: "nav-link" %>
</li>
```
t('header.login')という記述は、Railsが用意しているtメソッド（translateメソッドのエイリアス）に、header.loginを渡すことで、config/locales/views/ja.ymlに記述された日本語（ja/header/login）を取得しています。  

●Railsでのデコレーター  
Draper(ドレッパー)を導入する。  

【Draperとは】  
gemの一つでインストールすることでデコレーターを作成できるようになる。  
画面に表示させる内容の処理をerbファイルに次々記述していくと、  
分量が多くなり視認性が悪くなる。  
そのため、Draperを用いて別のクラスを用意してそこに画面表示に必要な処理部分を記述して置く。  

【decoratorとは】  
上記のDraperにおいて用紙された表示処理用のクラスのこと  
このdecoratorを使用した開発をdecoratorパターンと呼ぶ。  

【デザインパターン】  
デザインパターンとはコードを書くときのお手本やテンプレートのこと。  
再利用しやすく、保守、理解もしやすい。  

【heperとdecoratorの使い分け】  
コードの冗長化を防ぐためにロジックを外に切り出す機能として、  
helperが存在する。  
helperはモデルとは直接関係ないコードを記述する際に用いる。  
繰り返し使用する処理などを記述して置く。  
decoratorはそのモデルの拡張部分という認識で、モデルに関連した表示ロジックを記述して置く。  

【decorator内のメソッド】  
dockerにより生成されたdeoratorにはデフォルトで以下のメソッドが記述されている。  
・delegate_all  
基となるオブジェクトのすべてのメソッドを使用できるようにするためのメソッド  
・また基のオブジェクトのプロパティやメソッドにアクセスしたい場合はobjectを使用する。  
例)基のオブジェクトのlast_nameとfirst_nameにアクセスしている。
```
  def full_name
    "#{object.last_name} #{object.first_name}"
  end
```
