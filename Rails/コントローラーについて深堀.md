コントローラーについて深堀

【前提】  
コントローラーはMVCモデルにおける、Cである。  
役割についての復習。  
ユーザーからのリクエストをルーティングが受け取り、  
コントローラーへと渡される。  
コントローラーはルーティングの設定によってアクションを行う。  
DB操作がある場合はモデルへと指示を出し、モデルがDBを捜査した結果を返却される。  
返却されたデータの結果に基づいてビューに指示を出す。  
DB操作がない場合はモデル部分は割愛される。  
要は、コントローラーはモデルとビューの仲介役であり、  
ユーザーとビューとの橋渡し役でもあるということ。  

ユーザー→ルーティング→コントローラー→モデル→DB→コントローラー→ビュー  
省略するとユーザー→コントローラー→ビューのようなもの。  

【メソッドとアクション】  
コントローラーはApllicationControllerというクラスから継承されたクラスである。  

【フィルタ】  
フィルタはアクションの前後に実行される処理のこと。  
基本的にアクションの前後に処理を入れる際に使用する。  
before_action/after_actionでメソッド名を続けて記述する。  
指定されたメソッドがアクションの前後で起動する。  
注意点）  
上記のフィルタを継承元のApllicationControllerクラスに記述してしまうと、すべてのコントローラーにフィルタが適用されてしまう。  
これを回避するためにonlyやexceptという記述を追加して適用対象を選定する必要がある。  
補足）  
フィルタは定義した順に実行される。  
if文などで条件分岐させることもできる。  
子クラス側でskip_before_actionのように設定することで、  
定義されたフィルタをスキップすることも可能。  

【Parameters】  
パラメータは、ユーザーから送信される入力データのこと。  
POST/GET/パスなどの形式で送られてくる。  
送られたデータはRailsではparamsというハッシュ形式にして受け取る。  

【paramsメソッド】  
paramsメソッドは上記のユーザーから送信されたParametersを受け取るために使用される機能。  
特徴  
受け取ったデータをハッシュ(連想配列)のように扱う。  
params[:キー]でキーに対応したパラメータにアクセスする。  

【Strong Parameter】  
Railsのコントローラーで使われるセキュリティ機能のこと。  
ユーザーから送信されるパラメータのうち開発者が許可した項目だけ保存させる。  
不正なデータの流入を防ぐ目的。  
機能の背景：Railsに備わっているマスアサイメントという機能があり、これはフォームから送られた値をモデルの属性に割り当てるという機能。これにより、admin: true のような値を送信すると、  
自分自身に管理者権限を付与できてしまいます。  
例文）  
```  
private

def user_params
  params.require(:ユーザーモデル名).permit(:カラム名1, :カラム名2, ...).merge(追加カラム: 値)
end  
```  
private:メソッドが外部から呼び出されないようにする。  
params.require:必須パラメータを指定します。指定されたキーが存在しないとエラーになります。  
permit(:カラム名):許可する属性（カラム）を列挙します。ここに書かれていないパラメータは無視されます。  
.merge(追加カラム: 値):paramsに含まれていない値を追加で挿入したい場合に使います。
