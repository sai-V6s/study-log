ORMとActiveRecord

ActiveRecordはオブジェクト指向プログラミングとリレーショナルDBの橋渡しをするRubyのORMライブラリ。  
SQLの知識がなくても直観的にDB操作ができる。  

ORMとはオブジェクトとDBレコードを対応させる仕組み。  
Rubyのオブジェクトを通じてデータの操作をすることができる。  

【ActiveRecordの使い方】  
SQL文が簡単な文言で代用できる。  
例）以下は同じ内容のDB操作  
[AcitiveRecord]  
`user = User.find(1)`  
[SQL]  
`SELECT * FROM users WHERE id = 1 LIMIT 1;`  

【ActiveRecordの主要機能】  
①マイグレーション(移行)機能：既存のDBに新たに項目を追加したり、バージョン管理も行えるので、過去のDBの状態の戻すことができる。  
②アソシエーション定義：モデル同士を関連付けることができる。  
モデルとはMVCモデルにおけるモデルであり、アプリ内ではデータの種類ごとにモデルが存在する。  
![複数モデル](../images/複数モデル.png)  
注意点  
一文で簡潔な処理に見えて、裏のSQLでは大量の文が生成されてしまい、パフォーマンスに影響が出る場合がある。  
対策としてincludesなどであらかじめ処理に使用するであろうデータをまとめおいておく。  
joinsでテーブルを結合して置き、テーブル間の移動を減らす  
また、バリデーションなどを設けることによって適切なデータを保存しデータの整合性を確保することも重要。  

DB操作はCRUD(作成、読み取り、更新、削除)が基本になる。  
●作成  
newメソッドを使用して、インスタンスを作る。  
(インスタンスについてはオブジェクト指向.mdを確認)  
作成したインスタンスをsaveメソッドを使用するとDBに新たな項目としてDBに追加される。  
(すでに項目が存在する場合は自動で上書きされる)  
●読み取り  
findメソッドを使用して主キーをもつレコードを検索する。  
見つからない場合はエラーを返す。  
WHEREメソッドはfind+ifという認識で、条件に合致する値を検索できる。  
(SQLのWHEREは条件を絞るだけだが、こちらは検索機能も内包している。)   
●更新  
updateメソッドを使用して変更があった箇所だけ反映する。  
assign_attributesメソッドはsaveとともに使用して、即更新状態を保存しないで一旦値を代入するだけという状態にできる。  
そのため反映前にバリデーション処理なども設定できる  
●削除  
destroyメソッドかdeleteメソッドを使用する。  
destoryメソッドは処理にコールバックを設定して実行される。  
(コールバックとは、ある処理の前後に定型の処理を実行させる)  
deleteメソッドはコールバックを行わず、即座にレコードを削除する。  

【応用】  
●テーブル結合  
joinsメソッドはSQLのINNER JOINと同義。  
●事前に関連モデルを読み込む  
includesメソッドはN+1問題の回避に使用する。  
N+1問題は例えばデータを全件取得するというActiveRecord文を書くと、全件文のデータ数と同じ数SQL文が実行され高負荷となる。  
includesメソッドは関連データも読み込んでくれるので、追加のSQLは実行されなくなる。  

●includes関連のメソッド  
preloadメソッドも同様に事前に関連データを読み込む。  
差異としては、includesは場合によってはjoinしてテーブルを結合する場合がある点。別クエリ、つまりテーブルごとに処理を実行する。  
eager_loadメソッド  
includesはjoinが必要か判断したうえでデータを取得するが、  
eager_loadは必ずテーブルの結合を行う。  

●最初、または最後に位置するレコードを取得する。  
first\lastメソッド。背後のSQLでは昇順/降順に整列させた後に主キーを指定して取得している。  

●並べ替えや集合に使用されるメソッド  
orderメソッドは指定してカラムをアルファベット、日付または数字順に並べ替えを行う。  
limit/offsetメソッド  
limitは取得する件数を制限する、offsetは先頭からスキップする件数を指定できる。  
groupメソッドは特定のカラムでレコードをグループ化する。  
集計などと併用される。  
カラム列ごっそりひとまとめにするイメージ  

●条件を指定するメソッド  
where.notはwhereの逆で条件に一致しないデータを検索する。  
orメソッドwhereなどと併用して複数条件を指定可能にする。
